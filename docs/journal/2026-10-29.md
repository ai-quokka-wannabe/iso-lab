## Four Rust Advisories in the Fetch Tool's TLS, Patched

Written by iso-lab's night staff, an AI agent; not by the maintainer.

A push at about 21:10 UTC reported "4 vulnerabilities on [the] default branch (1 moderate, 3 low)", after `npm audit` had
come back clean. This session cannot read GitHub's alerts (the API answers 403), so every pinned dependency in
`Cargo.lock`, `notebooks/requirements.txt` and `package-lock.json` was queried against the public
[OSV database](https://osv.dev/) (`https://api.osv.dev/v1/querybatch`, 184 packages). Only four crates matched, all
reached through `ureq`'s TLS in the `fetch` crate, which downloads the reference recordings:

- `rustls` 0.23.45: four advisories published on 2026-10-27, fixed in 0.23.46. One is moderate:
  [GHSA-c8m5-c952-6cm4](https://github.com/advisories/GHSA-c8m5-c952-6cm4), where `Debug` formatting of a session
  exposes TLS secrets. Three are low:
  [GHSA-h2v8-394m-p7vv](https://github.com/advisories/GHSA-h2v8-394m-p7vv),
  [GHSA-vp88-798v-h67f](https://github.com/advisories/GHSA-vp88-798v-h67f) and
  [GHSA-w44r-93j7-qv28](https://github.com/advisories/GHSA-w44r-93j7-qv28). This matches GitHub's count.
- `rustls-webpki` 0.103.15, `webpki-roots` 1.0.9 and `webpki-root-certs` 1.0.9: RUSTSEC-2026-0381 to 0383,
  distrusted emSign intermediates, fixed in 0.103.16 and 1.0.10.

`cargo update -p rustls -p rustls-webpki -p webpki-roots -p webpki-root-certs` moved them to 0.23.46, 0.103.16, 1.0.11
and 1.0.11; only `Cargo.lock` changes. The licences are the same as before: Apache-2.0 OR ISC OR MIT, ISC, and
CDLA-Permissive-2.0 for both root-certificate crates. With the toolchain 1.99.1:

- `cargo fmt --check`, `cargo clippy --locked --all-targets -- --deny warnings` and `cargo test --locked` pass, with
  63 tests passed and none failed;
- the same OSV query over the new `Cargo.lock` finds no advisory in any of its 88 crates.

The fetch tool's own live download was not re-run tonight; its MD5 check guards every file it fetches.
