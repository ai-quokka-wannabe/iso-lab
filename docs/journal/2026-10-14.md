# 2026-10-14

## Dependabot Alerts Triaged

Written by iso-lab's day staff, an AI agent, at the maintainer's request; not by the maintainer.

- **The task**: the three Dependabot alerts on `main` that STATE.md listed under *Blocked*. This session cannot read
  GitHub's alerts (the API answers 403), so they were identified from the repository's manifests and the public
  [OSV database](https://osv.dev/) instead.
- **What it did**: `npm audit` (npm against the committed `package-lock.json`, markdownlint-cli2 0.23.3) reports
  exactly GitHub's count, one high, one moderate and one low, all inside the markdown linter, a development tool
  only. Each advisory was read from `https://api.osv.dev/v1/vulns/<id>`, and each dependency's use was read in
  `node_modules`:
  - **High, [GHSA-vfj7-8cjw-p6xm](https://osv.dev/vulnerability/GHSA-vfj7-8cjw-p6xm)**: `braces` 3.0.3, through
    `micromatch` 4.0.8; deeply nested brace patterns can exhaust the stack. No version is fixed: the advisory
    covers every version through 3.0.3, the latest. The linter passes `braces` only glob patterns from its command
    line and configuration, which are the lab's own (`"**/*.md"` and the ignore list), so the lab's use cannot
    trigger it.
  - **Moderate, [GHSA-r4xh-jqrq-34v2](https://osv.dev/vulnerability/GHSA-r4xh-jqrq-34v2)**: `smol-toml` 1.8.0;
    quadratic-time parsing of a TOML document. Fixed in 1.9.0, but markdownlint-cli2 pins exactly 1.8.0, on its
    `main` as well. It is loaded only for a configuration file ending in `.toml`
    (`markdownlint-cli2.mjs`, the configuration reader); the lab's is `.markdownlint-cli2.jsonc`.
  - **Low, [GHSA-238p-pmpm-9mq7](https://osv.dev/vulnerability/GHSA-238p-pmpm-9mq7)**: `katex` 0.16.47, through
    `micromark-extension-math` 3.1.0; KaTeX can carry a prototype pollution some other flaw has already caused.
    Fixed in 0.18.2, but its parent allows only `^0.16.0`, on its `main` as well. KaTeX is imported only by the
    extension's HTML renderer (`lib/html.js`), and markdownlint imports only its parser, so KaTeX is never loaded.
- **What came out**: none of the three is reachable, and none has a clean fix. `npm audit fix --force` would
  downgrade the linter to 0.21.0 and fix nothing; npm `overrides` could force the patched `smol-toml` and `katex`
  past what their parents declare, which would quieten the scanner at the cost of running the linter on combinations
  its authors never tested, and would leave `braces` flagged. Neither was done. The alerts should be dismissed -
  "vulnerable code is not actually used" for `smol-toml` and `katex`, "risk is tolerable" for `braces` - and
  Dependabot will propose the fix when markdownlint-cli2 or micromark-extension-math releases one.
- **What failed**: this session cannot dismiss the alerts; its GitHub access refuses writes to them (HTTP 403). The
  dismissal waits on the maintainer, as STATE.md says.
