  alone - the cloud machine is Linux, so the Windows and macOS routes of the world's guides (rc-worm's
  `first_life.ps1` among them) are left aside.
- **What it did**: queried Zenodo's API for the Open Worm Movement Database community and for the CeMEE
  Multi-Worm Tracker record, and opened one N2 record's features file and WCON file. The world was not built.
    - Every record answering `title:"N2 Schafer Lab N2"` in the community, listed 25 a page in a stable order
      and counted by record id, with the fields of each description read and the file sizes summed, by this
      script (Python 3.13, standard library only; `python3 -I n2_survey.py`):

        ```python
        import json, re, statistics, time, urllib.parse, urllib.request
        from collections import Counter
        B = "https://zenodo.org/api/communities/open-worm-movement-database/records"
        recs, page = {}, 1
        while True:
            u = B + "?" + urllib.parse.urlencode({"q": 'title:"N2 Schafer Lab N2"', "size": 25, "sort": "oldest", "page": page})
            for a in range(8):
                try:
                    d = json.load(urllib.request.urlopen(u, timeout=60)); break
                except Exception:
                    time.sleep(2 * 2 ** a)
            else:
                raise SystemExit(f"gave up at page {page}")
            h = d["hits"]["hits"]
            if not h:
                break
            for r in h:
                recs[r["id"]] = r
            page += 1
        print("total", d["hits"]["total"], "unique", len(recs))
        def field(r, k):
            m = re.search(r"<b>" + k + r"</b>\s*:\s*([^<]*)<", r["metadata"]["description"])
            return m.group(1).strip() if m else None
        print("licences", Counter(r["metadata"].get("license", {}).get("id") for r in recs.values()))
        for k in ("sex", "stage", "food", "habituation"):
            print(k, Counter(field(r, k) for r in recs.values()))
        sub = [r for r in recs.values() if (field(r, "sex"), field(r, "stage"), field(r, "food"), field(r, "habituation")) == ("hermaphrodite", "adult", "OP50", "30m wait")]
        print("subset hermaphrodite+adult+OP50+30m wait", len(sub))
        def base(r):
            return r["files"][0]["key"].rsplit(".", 1)[0].replace("_features", "").replace(".wcon", "")
        mut = [r["id"] for r in sub if not base(r).startswith("N2 ")]
        print("subset whose file names do not start with 'N2 '", len(mut), sorted(mut)[:25])
        for name, recset in (("all", list(recs.values())), ("subset", sub)):
            for suf in ("_features.hdf5", ".wcon.zip"):
                s = [f["size"] for r in recset for f in r["files"] if f["key"].endswith(suf)]
                print(name, suf, len(s), "sum %.2f GB" % (sum(s) / 1e9), "median %.2f MB" % (statistics.median(s) / 1e6))
            s = [f["size"] for r in recset for f in r["files"] if f["key"].endswith(".hdf5") and not f["key"].endswith("_features.hdf5")]
            print(name, "full .hdf5", len(s), "sum %.2f GB" % (sum(s) / 1e9), "median %.2f MB" % (statistics.median(s) / 1e6))
        print("md5 on every file", all(f["checksum"].startswith("md5:") for r in recs.values() for f in r["files"]))
        years = Counter(r["metadata"]["title"].split("|")[1].strip()[:4] for r in recs.values()); print(sorted(years.items()))
        ```

    - Record [1011832](https://doi.org/10.5281/zenodo.1011832): both files downloaded matched their MD5
      (`675079bc...` features, `b25b1656...` WCON); read with h5py 3.16.0 under Python 3.13: 29256 frames,

## H10's First Test: Phase Against Real Memory

Written by iso-lab's night staff, an AI agent, at the maintainer's request in the same session.

- **The task**: the maintainer asked for the "quantum-like mind" to be tried now (STATE.md item 6). H10 enters
  [the hypotheses](../hypotheses/README.md) as the maintainer's hunch, and its smallest test was run: at the same
  memory budget, does a complex-valued associative memory hold more retrievable information than a real one?
- **Pre-registered first**: the method, the measure, the refutation rule and an implementation control were
  committed in [notebooks/h10_phasor_memory.ipynb](../../notebooks/h10_phasor_memory.ipynb) (commit `cd9014d`,
  19:26 UTC) before the first run. One flaw was caught and fixed before that commit, by reading the code, not by a run: the
  control first ran the same real-valued code path as the real network, so it could not have caught an error in the complex arithmetic;
  it now runs the complex path with two phases on the same seeds.
- **The run**: `jupyter nbconvert --to notebook --execute --inplace notebooks/h10_phasor_memory.ipynb`, Python
  3.13.16 with the pins of `notebooks/requirements.txt` (numpy 2.5.4), seeds 0 to 19, bootstrap seed 20261013;
  about four and a half minutes on the cloud machine.
- **What came out**, in bits retrievable per real number stored, mean over 20 seeds:
    - real Hopfield network, 256 units: 0.1119 (sd 0.0076);
    - phasor network, 181 units of four phases: 0.1149 (sd 0.0061);
    - phasor minus real, paired: +0.0030, 95% interval [-0.0010, 0.0068];
    - control, the complex code with two phases: identical to the real network on every seed (difference 0.0000),
      so the complex arithmetic reproduces the real case exactly.
- **The verdict, by the rule fixed beforehand**: the interval includes zero, so the phasor network is *no better*,
  and this test refutes H10's memory claim at this level. It also costs twice the multiply-adds per sweep
  (131 044 against 65 536), so per multiply-add it carries about half as much: from the unrounded mean, 0.114862 x 65 522 / 131 044 =
  0.0574 bits against 0.1119.
- **What failed or surprised**: the phasor network holds fewer patterns before it breaks - its mean recall falls below
  0.9 between loads 20 and 22 (0.9600, then 0.8975 unrounded), the real network's between 28 and 30 (0.9125, then
  0.8725) - yet each of its patterns carries more bits (362 against 256), and the two effects nearly cancel. A first
  draft of this line read the crossing off the rounded output and got it wrong; the verifier caught it. A watcher written to wait for the run matched its
  own command line and reported "still running" after the run had ended; it now waits on the process id.
- **Limits the verifier found, recorded**: the success rule (overlap at least 0.98) tolerates up to about 1.7% wrong
  units for the phasor against 0.8% for the real network, and the cues corrupt 26 of 256 units against 18 of 181 -
  both favour the phasor, so they strengthen the null result rather than weaken it. A field exactly between two
  phases (0.32% of phasor updates, by the verifier's count) is resolved by `argmax`, not by keeping the state, which
  the pre-registration did not specify. The score, a per-seed maximum over a coarse grid of loads, is biased upward
  for both networks. The notebook's attribution of its update rule to Noest 1988 and Jankowski et al. 1996 is
  unchecked until those papers are read - low confidence in that sentence; the result does not rest on it. Only
  the four top-level packages are pinned. The next test fixes all of these first.
- **Kept, not discarded** (the maintainer's ruling, below): the notebook stays with its outputs, H10 records the
  result under *Tested so far*, and STATE.md's new *To Revisit* list names the next attempt - phase where the hunch
  says it matters: the undulation phase of a rhythm generator, interference between two paths (F1), more phases.
- **A slip, caught**: a STATE.md change was first committed on the local `main` rather than this branch; the push
  to `main` was refused, nothing reached GitHub, and the commit was moved to the branch.
